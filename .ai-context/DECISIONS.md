# Архитектурные решения — ArchetypeOS

## ADR-001: Vanilla JS only (зафиксировано)
**Дата:** до сессии 0  
**Контекст:** Проект задуман как лёгкий встраиваемый виджет (iframe в Tilda).  
**Решение:** Никаких фреймворков, никаких сборщиков. Чистый HTML/CSS/JS.  
**Последствия:**
- + Мгновенный деплой, нет build-шага
- + Лёгкий вес, быстрая загрузка
- − Ручное управление состоянием
- − Риск коллизий глобальных имён

## ADR-002: Глобальные переменные как модульная система
**Дата:** до сессии 0  
**Контекст:** Нет сборщика → нет ES6 modules.  
**Решение:** Каждый JS-файд объявляет глобальный объект (Tracker, Pivot, ArchetypeThemes...). Загрузка через `<script>` теги в index.html в правильном порядке.  
**Порядок загрузки:**
```
data.js → tracker.js → interpreter.js → archetype-themes.js → pivot.js
→ diagnostic.js → archetype-result.js → engine.js → init-tracking.js
```

## ADR-003: diagnostic.js заменяет панель контроллеров
**Дата:** до сессии 0  
**Контекст:** Два режима работы: ручное управление вектором (engine.js) и экспресс-тест (diagnostic.js).  
**Решение:** diagnostic.js полностью перезаписывает `innerHTML` `#panel-controllers`. Это конфликтует с engine.js, который ожидает jog-dial элементы в DOM.  
**Статус:** ⚠️ Известный баг/особенность. Нужно либо разделить view-режимы, либо переключать корректно.

## ADR-004: Lock → Pivot отключён
**Дата:** до сессии 0  
**Контекст:** Interpreter.onLock должен был триггерить Pivot.execute().  
**Решение:** В `init-tracking.js` коллбек закомментирован. UI не трансформируется автоматически при lock.  
**Причина:** Вероятно, слишком агрессивное поведение для пользователя.  
**Статус:** Ожидает решения — включить с более мягкими порогами или оставить ручным.
